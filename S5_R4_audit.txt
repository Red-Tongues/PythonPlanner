## Fix list (on PR #3, after the build tidy; data-model-independent)
1. **MR1 Atomic binding guard.** Every binding-dependent run write (dispatch, accept, publish, park, approve) does a **packet-row CAS** in the same transaction:
   - `UPDATE packets … WHERE id, version, status, locked=false, active_run_id, fencing_token, gate_revision, input_hash match, and the row is head`;
   - rowcount 1, otherwise StaleRun.
   
   This works on both dialects (Argon's design). Add a PG barrier test at the `before_scopes` seam.
2. **MR2 + MR3 Mandatory fence; approval-bound user dispatch.**
   - System actors must pass a valid `KernelLock` (FencedOut otherwise).
   - A user dispatch is allowed only via `approve_run` with a just-approved, run-bound confirmation, and only while the packet is `running` with no hold or block.
   - No other path can dispatch a parked run.
3. **MR4** Approved resume renews the run and packet leases atomically.
4. **MR5** Confirmed split keeps the approving user as actor (or adds an explicit kernel continuation row bound to the consumed confirmation).
5. **MR6** A retry requires the previous attempt's retry-eligible outcome, or recorded deadline expiry.
6. **MR7** Separate dispatch sequence from chargeable attempts: exit-3 park/resume never consumes the attempt budget.
7. **MR8** Staling a restricted packet's run records a deferred-recovery condition, processed once the restriction clears (E7 still applies). No ownerless `running` packets.
8. **MR9** A stale-binding approval commits an audited stale disposition and retires the unusable confirmation. "Stays pending" applies only to recoverable refusals (pause, budget).
9. **MR10** Reconciliation includes legacy `claimed` runs.
10. **MR11** Budgets: non-negative integer validation plus DB CHECK constraints.
11. **MR12 + MR13** Race tests:
    - propagate unexpected exceptions; assert both workers' allowed outcomes; fail on timeout;
    - integrated dispatch/acceptance tests with an effect-counting fake adapter.
12. **GR1** `cancel_run` clears `active_run_id` only with a guarded UPDATE (`WHERE active_run_id = run.id AND fencing_token = run.fencing_token`).
13. **GA-R1** `reject_run`'s packet CAS also guards `active_run_id` and `fencing_token`.
14. **GA-R2** Failure-budget approval checks that `confirmation.entity_version == packet.version`, and applies the status transition and gate bump atomically.
    *Note: failure-budget behaviour will be replaced by the T1 failure indicator later; fix only the atomicity.*
15. **GA-R3** `packet_scopes`: a trunk packet (`root_id` NULL) includes its own branch scope, so a branch pause blocks the trunk too.
16. **GA-R5** Verify the `budgets.reserve` audit/flush ordering. Record the event before `session.add`, or use `no_autoflush`. Add a test.

### What the PostgreSQL run found, and the fixes
There was **no CI run for 66076d0**: PR #3 conflicted with the force-updated `main` (PROGRESS.md), so GitHub built no merge ref. I ran PG 16 locally and got 4 failures; the SQLite suite had 1 of the same.
1. **Real bug (75e801e, MR9):** a torn read under READ COMMITTED. `approve_run` read the run at G, a concurrent rejection committed (G+1 on both rows), then it read the packet at G+1. It took the stale path and **staled the run the user had just rejected**, releasing the packet's ownership. Now the stale disposition first retires its own confirmation with the once-only CAS, so a decided confirmation makes the approval lose. A deterministic regression test injects the torn read; it fails without the fix on both dialects.
2. **Test bug, both dialects:** the late-result test rejected the legitimate `"duplicate"` outcome.
3. **Test bug, PG:** the pause-first test asserted that the dispatcher finishes while the pause is uncommitted. On PG the dispatcher waits on that row lock, so the two deadlocked. The bounded hold is restored.
4. **Test bug, PG:** `pytest.raises` sat inside `begin_nested`, so the savepoint was RELEASEd on an aborted transaction. The order is swapped.

### PM observations
- **(b) `_resume_after_budget` input_hash (Golden Rule 5): fixed (ad66ca3).** Before/after now carry the old and new hash when the context changed.
- **(c) `budget.reserved` before success: confirmed safe, and moved anyway (39f5385).** The only caller chain is `approve_run → authorise_dispatch → reserve`, and nothing in `src/` catches `BudgetExhausted`, so every caller rolls back. The event and reservation rows are now added only after every counter UPDATE succeeds (still under `no_autoflush`, so the flush guard sees them together). A future Stage B caller that swallows the error can no longer leave an event claiming a reservation. The rollback contract stays, because it is what undoes earlier counter UPDATEs.
- **(a) Split rejection `awaiting_confirmation → ready` deviates from D8. Recommendation: remove it** (not changed here; CFO/PM decision).
  - D8 row 61 says "awaiting_confirmation → held — rejection (any type) · user, reason required".
  - `ready` is a kernel readiness decision. A user moving a packet straight to `ready` skips readiness. `_approve_review` deliberately avoids exactly that (owner → `evaluating_pre`, then the kernel admits).
  - Every other rejection (exit 3, failure budget) goes to `held`.
  - Cost: one more owner step (release `held`). If the CFO wants no extra step, use the review pattern instead (user → `evaluating_pre`, readiness re-admits in the same transaction), not a direct user `→ ready`.
  - Related and also not in D8: the agent added kernel `ready → awaiting_confirmation` when a split confirmation is requested. **Recommend keep.** D8 row 60 (`awaiting_confirmation → waiting_for_children`, split approval) needs the packet in `awaiting_confirmation`, and split triggers fire on `ready` packets. It is the same kind of gap-fill as P1.
