## 1. Mutable developing genPacket, sealed snapshot, child lineage (Q1, Q6)

**Kept from v2 §1, §6 and §7 unchanged:**
- `packets` is the live row of a **developing** genPacket (`draft`, `evaluating_pre`, `ready`, `queued`). The CFO may read and edit it in SQL.
- **Outbox (H1):** an AFTER UPDATE trigger on `packets` inserts raw old/new values plus `tx_id` into the transient `raw_revision_outbox`. The kernel writes `content_blobs`, then inserts the final hash-only `field_revisions` row (with `manifest_hash`), then deletes the outbox row. `field_revisions` is never updated.
- **Version bump (H2):** audit triggers only INSERT. One separate, column-guarded trigger may bump `version`.
- **Producer attribution (§8):** `producer = CASE WHEN OLD.version = NEW.version THEN 'user_sql' ELSE NEW.last_producer END` on SQLite. Every kernel write sets `last_producer` **and** bumps `version`.
- Drain the outbox on startup and every tick, before any dispatch (H6). Group multi-field edits by `tx_id` / `revision_group_id` (H8). An unenriched revision is ineligible for generation or sealing (GPT-6.1 item 2).
- **Trigger rules:** enumerate the audited semantic columns; `UPDATE OF` plus a real change test. Tests T1–T6 from v2 §8 go into M3a on both dialects.
- **Content blobs:** large text is stored once and referenced by hash.

**Changed by v3:**
- **One seal per genPacket.** When `gen_eva` completes, the genPacket is frozen into `sealed_bundles`. That means the canonical JSON snapshot, its hash, and its `gen_eva` grade. The row is then locked. `UNIQUE(packet_id)` replaces v2's `UNIQUE(packet_id, episode_no)`. `lifecycle_episodes` stays dropped and episode numbers are gone.
- **No re-opening.** v2's "re-opening sets `packets.status` back" is withdrawn. Any further work is a **child genPacket** with:
  - `parent_id` = the sealed parent;
  - `root_id` = `parent.root_id or parent.id`;
  - `depth` = `parent.depth + 1`;
  - the parent's sealed bundle ID/hash recorded on the child (Q6).
- **No `supersedes_id` cloning of genPackets.** A core edit of a developing genPacket is an in-place edit captured by the outbox. A sealed genPacket is never edited. `trg_packets_immutable_when_locked` stays and is never disabled.
  - Whether projects and objectives keep `supersedes_id` versioning is **OQ21**.
- **Intra-packet based-on chain (Q6):**
  - `prompt_description` → pre-eva fields / `locally_drafted_examples` → `generation_output` + thinking → `gen_eva` → sealed snapshot → child genPacket;
  - each stage records the hash of the stage it was derived from.

**Requirement F, reworded (needs the CFO's approval of the wording, OQ26):**
> Sealed bundles, field revisions, generation attempts, eva passes and events are immutable. A developing genPacket is editable, and every edit is recorded. A sealed genPacket is never edited or re-opened; further work on it is a child genPacket.

CLAUDE.md Golden Rule 1 still says "Corrections create a new version (`supersedes_id`)". It must change with the reworded Requirement F. It is not edited in this docs-only change.

## 2. Context changes: `question_context`, not invalidation (Q2)

**Retired:**
- `require_current_context` hard invalidation, and `bump_scope` kicking `ready`/`queued` packets back to `evaluating_pre` on a Project/Objective edit;
- `v_field_consensus` setting `is_current = 0`, `status = 'pending'`, `final_value = NULL` when the target hash differs;
- v2's `drift_risk` as a separate score.

**Design:**
1. **`packets.input_hash` is intra-packet only.** It covers the packet's own stage-1 definition: `title`, `prompt_description`, `response_contract`, `repo_target_path` (directive C.i.2.1).
   - v2's binary manifest also had field-definition, preset and contract versions and the repo commit. Whether a change to those still invalidates is **OQ23**.
2. **`eva_context_links`.** Each evaPacket run registers the context it read, deterministically and with no LLM call:
   - `source_type`: `project` / `objective` / `packet`;
   - `source_ref` and `source_hash` at evaluation time;
   - `link_strength`: `direct` or `peripheral`.
   A structural source is upgraded to `direct` when a **verified** SUPPORT/CONTRADICTION quote from passes 3–6 cites it. A hard dependency is `direct`. Today's quotes carry no source attribution, so how a quote is attributed is **OQ22**.
3. **`question_context`.** Per evaluative field: `question_context` (0/1) and `question_context_count`. They are computed in SQL by comparing each link's stored `source_hash` with the source's current hash.
   - Evaluations stay tied to the context snapshot that produced them and **stay usable**: no nulling, no `pending`, no stall.
   - Not computed for `waiting_for_children` or `archived` packets.
   - How `direct` and `peripheral` are weighted is **OQ4**.
4. `question_context` feeds genQueue/evaQueue maths (Q1 v2 note).
   - A packet with `question_context_count > 0` belongs in evaQueue for a refresh, unless it is in the position 0–2 lockout.

## 3. Failure model: crashes vs grades; no breaker (Q3, Q4, Q5)

**Retired:** `enforce_failure_budgets`; the K = 3 same-prompt breaker; the linked-lineage retry budget; the 10% bounded prior.

**Design:**
- **No identical reruns.** Once a genPacket has been generated and graded by `gen_eva`, it is sealed. However good the grade, the task returns as a **re-imagined child genPacket** carrying the parent's output, `gen_eva` critique and updated context.
- **`gen_eva` is a direct gate.** It runs immediately after a generation that produced gradable output, with no queue maths. It grades output and recorded thinking (v2 §3 thinking rules stay: redacted, access-controlled, never the sole evidence). Then it seals the parent and spawns the child. How the composite grade is computed is **OQ16**.
- **Crash ≠ grade (Q4).** A crash is a timeout, disconnect or adapter fault with no gradable output (`generation_output IS NULL`). It:
  - increments a separate `crash_count`;
  - nudges route health;
  - leaves the genPacket **unsealed**;
  - is never a quality signal.
  Where the packet goes after a crash, and what bounds repeated crashes, is **OQ18**.
- **Substantive failure.** A completed generation with a low `gen_eva` grade. It seals the parent with that grade and spawns a high-priority child.
- **Lineage history (Q5).** Grades, evidence tags and crash telemetry stay queryable through `parent_id` / `root_id`. No synthetic carry-over, no per-cause confirmation.
- **User feedback (Q3(i))** is a mathematical weight in queue maths: confirmations, waivers, manual SQL edits, overrides, grade adjustments. See the Q1 v2 note and **OQ9**.
- v2's exact failure product `A = min(10000, (∏(10000+c_k) − 10000^n) // 10000^(n−1))` is not mentioned by the directive. Each genPacket now has at most one graded attempt, so `A` has nothing left to aggregate within a packet. Whether it survives as a lineage-level input is part of **OQ7**.

## 4. Provisional work (unchanged from v2 §4)
- Failed or partial output lives in `content_blobs`, linked from `generation_attempts`, plus `refs/provisional/<packet_id>/<attempt_no>`.
- There is no shared provisional branch.
- Writing into the working tree (uncharted paths only) needs the `@ORCHESTRATOR:PROVISIONAL` banner, a syntax check and a secret scan.
- Provisional refs are pruned when the packet seals (H7).
- Placeholder flagging (C39, Q-P6) is unchanged.

## 5. Running generations are never overridden (Q7)

**Retired:**
- the `gate_revision` and upstream `input_hash` checks in `runs.binding_mismatch`, and the run-row staling they drive;
- v2 question 7's "cancel the run, so your edit wins".

**Kept:**
- monotonic fencing tokens, leases, the kernel lock;
- the claim CAS;
- an explicit owner halt (close / BLOCK) stops a run. Whether HOLD and pause also do is **OQ19**.

**New: the position 0–2 lockout.**
- evaPackets are excluded from evaQueue, and cannot run, when they belong to, or are directly related to, a genPacket at genQueue positions 0, 1 or 2.
- Which statuses count as position 0 is **OQ1**. How positions are numbered is **OQ2**. What "directly related" means is **OQ3**.
- A user's SQL edit of a running genPacket never cancels the run. Where that edit lands (sealed parent or child) is **OQ20**.
