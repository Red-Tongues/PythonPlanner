# Review R0 — panel findings on the plan and milestone specs (commit 9a6f345)

Panel: **GH** = GitHub Copilot · **MC** = Microsoft Copilot · **GE** = Gemini (Argon). Each reviewer worked independently from the same material (passes 1–2 analogue). Findings are condensed faithfully; wording lightly shortened.

| ID | Sev | Location | Problem | Suggested change |
|---|---|---|---|---|
| GH1 | high | M1 §5; Plan §6 | Locking on completion is an app action; a raw SQL update can set a terminal status without `locked`, leaving completed work mutable. | Enforce terminal-status ⇒ locked in the DB; test raw-SQL complete/unlock/update/delete and supersede on both DBs. |
| GH2 | high | Plan §7; M2 §4 | Consensus acceptance under-specified: agreement accepted regardless of confidence; no absolute confidence floor; contradiction counting undefined. | Confidence floors; exact dispute/evidence rules incl. ties and unverified evidence; per field kind; SQL truth-table tests. |
| GH3 | high | Plan §8; M2 §4 | Priority inputs have no scales/bounds; unbounded `age_hours` dominates; anti-starvation not guaranteed for late or retried packets. | Define units/bounds, normalise and cap ageing, state a fairness guarantee; test simulated time, retries, extremes on both DBs. |
| GH4 | high | M1 §4; M2 §4 | Centralised trigger DDL ≠ view portability; Python fallback may diverge from SQL or between dialects. | One semantic contract per view, documented per-dialect implementations, cross-dialect fixture tests asserting identical rows/NULLs/ordering. |
| GH5 | high | M3 §1, §4 | No recovery protocol for external side effects: crash after workbench submit, file write, commit or scan but before DB record duplicates work or desyncs DB/repo. | Run states + idempotency keys; persist intent before dispatch; reconcile on restart; repeatable writes/commits; crash tests between each side effect and DB update. |
| GH6 | high | M2 §3, §5; M3 §1 | No atomic packet claiming between kernel processes and GUI actions → duplicate evaluations, children or runs. | DB-backed claim/lease with expiry; uniqueness constraints or idempotency keys for evaluations, branches, runs; concurrency tests. |
| GH7 | medium | M2 §3; M3 §3–4 | Contracts are shape checks only; no versioned schemas, strict extra/oversize handling; `ast.parse` ≠ safe/correct code. | Version and persist the contract per run; strict parsing, size limits, semantic validators; quarantine artifacts until tests/policy pass; confine paths to repo root. |
| GH8 | medium | M1 §9; M2 §8; M3 §8 | Tests emphasise SQLite and happy-path fakes; no required PostgreSQL parity for M2/M3, nor crash, concurrency, adapter-failure, autonomy-boundary tests. | CI both dialects for views and transitions; deterministic fault injection for retries, crashes, concurrent workers, timeouts, approval gates, immutability bypass. |
| MC1 | high | Plan §6–8; M1 §4–5; M2 §4 | Portability lacks a semantic contract (JSON/tag expansion, NULLs, timestamps, aggregation, recursive lineage); Python fallback may expose different decisions; no schema/trigger/view upgrade path. | Typed result contract + shared fixtures per view; UTC, NULL semantics, precision, ordering; **versioned migrations** for tables, triggers, views, seeds; identical results on both DBs incl. after upgrade. |
| MC2 | high | Plan §6, §10, §13; M1 §4–6; M3 §4 | Row locks ≠ immutable history: INSERT of completed-but-unlocked rows unspecified; mutable project/objective context, field definitions and settings change the meaning of past evaluations; artifact hash doesn't protect the file; supersede rule unclear. | Enforce lock invariants on INSERT and UPDATE; snapshot/version all decision inputs; bind accepted artifacts to git commit IDs + hashes; runtime credentials must not own DDL; generated work must not touch the orchestrator DB. |
| MC3 | high | Plan §7; M2 §3–4 | Consensus not deterministic: passes have no evaluation-cycle identity (stale runs mix); 3-pass text can't supply cross/self inputs; one-sided NULL, incomplete passes, ties, split mapping undefined; zero verified evidence can still be accepted; no per-tag confidence. | Evaluation-cycle ID bound to packet/context revision, field-definition version, models, pass-plan version; aggregate only complete cycles; decision tables for NULL/missing/ties/text/split; per-tag scoring; minimum verified evidence or stay unresolved. |
| MC4 | high | Plan §8; M2 §4–5; M3 §1 | Ageing preserves relative order; progress not proven; failures re-queue forever; persistent split thresholds re-fire; unbounded branch depth; trunk still executable. | Separate eligibility from rank; bound weights/boosts; max-wait rule; retry backoff + lifetime failure budget; idempotent branching keyed by packet-version × rule-version; depth/descendant caps; trunk → waiting-for-children; deterministic roll-up. |
| MC5 | high | M1 §2; M2 §1–3; M3 §3–4 | Pydantic asked to carry more assurance than specified: no strict coercion/extra-field rules, no schema delivery to models; valid JSON ≠ correct task; target-path confinement unspecified; error-feedback retries can't fix missing context. | Versioned strict field-specific contracts (reject unknown keys/out-of-vocabulary); pass compact schemas with capability fallback; separate structural vs semantic acceptance; confine paths (no traversal/symlinks); after bounded repairs escalate or quarantine. |
| MC6 | high | Plan §9–11; M3 §1–2, §4–6 | Crash safety and three-channel concurrency asserted, not specified: sequential tick blocks on workbench/scan; no claims/leases/duplicate-kernel rule; files+git not atomic with DB; late results/approvals apply after policy changes. | Persisted run state machine; atomic claims, expiring leases; bounded independent channel workers; durable outbox/inbox + idempotency keys; atomic file publication; startup reconciliation; bind results/approvals to input/output hashes and policy revisions; pause/drain semantics; per-operation deadlines. |
| MC7 | high | Plan §2, §11, §13, §15; M3 §2, §5, §8 | Prototype can *demonstrate* autonomy without delivering it: workbench consumer is a human/auto-responder; quality scan may be skipped; reports not bound to commits; no rule for adverse findings. | Require one supported unattended workbench consumer in v1 **or** label complex production as externally blocked and narrow the claim; visible blocked reasons; bind scans to exact commits; define skip/failure policy and whether findings block acceptance. |
| MC8 | high | M1 §9; M2 §8; M3 acceptance | Acceptance tests prove wiring, not hours of unattended progress, recovery, fairness or small-model reliability; adversarial cases not enumerated. | Cross-DB invariant tests; fault injection at every durable boundary (e.g. after commit, before DB ack); concurrent claims, late inbox results, approval races, branch replay, starvation, retry exhaustion; bounded multi-hour soak; separate benchmarks of real models; fakes for routine CI. |
| GE1 | high | M2 §4; Plan §6–8 | View functions differ by dialect (`json_each` vs `jsonb_array_elements_text`, `julianday` vs `EXTRACT(EPOCH…)`, SQLite has no `VAR_POP`); Python fallback breaks inspectable DB state. | Dialect-aware DDL (SQLAlchemy `@compiles` or per-dialect view files); CI asserts identical view rows on both DBs. |
| GE2 | high | M1 §4–5; Plan §3F, §6, §10 | Projects/objectives lack lock/version columns though §10 says interruptions create new versions; `supersede_packet` leaves children and artifacts on the old row. | Add `locked`, `version`, `supersedes_id` (+ triggers) to projects/objectives; `is_active_head` on packets; supersede atomically archives (locks) the old row and re-points active children. |
| GE3 | high | Plan §7; M2 §3–4 | Re-evaluations mix historical passes into consensus; 3-pass text cap leaves `value_a` unscored; single-NULL asymmetry undefined. | `eval_cycle_id`, consensus over latest complete cycle; text cap → 4 passes (P1–P4, cross only, confidence = cross/10); single NULL: accept non-null if confidence ≥ 0.7 else disputed. |
| GE4 | high | M3 §1–2, §6–7 | No reconciliation for packets/runs left `evaluating`/`in_progress`/`running` after a crash; file-drop polling blocks the tick; GUI + kernel on SQLite → "database is locked". | Startup reconciliation with `heartbeat_at` + lease timeout; non-blocking workbench (`awaiting_inbox` checked per tick until `timeout_at`); SQLite `journal_mode=WAL` + `busy_timeout=5000` on every connection. |
| GE5 | medium | Plan §8; M2 §4–5 | `objective_priority`, `manual_boost`, `failed_runs` missing from schema; NULL ambiguity nulls the formula; unbounded ageing re-runs broken packets forever. | Add `priority_level` to objectives, `manual_boost` to packets; `COALESCE(ambiguity, 5)`; count failures from `channel_runs`; circuit breaker: `failed_runs ≥ 3` → `awaiting_confirmation`. |
| GE6 | medium | Plan §7, §9; M2 §2–3 | Exact-substring evidence fails on small models (smart quotes, markdown, ellipses); raw ValidationError retries confuse small models; code/markdown inside JSON breaks on escaping. | Normalise before matching and never fail the parse on unverified quotes; one-line corrective retry messages; fenced code-block extraction with front-matter instead of JSON-wrapped code. |
| GE7 | medium | Plan §5.2, §8; M3 §4–5 | Children can re-split forever; content-evaluation packets could be routed to generation channels. | `depth` and `packet_kind` (`task` / `content_eval`) on packets; `depth < max_branch_depth` (2); split parents → `processed`; content-eval packets terminate after consensus or raise a confirmation. |
| GE8 | medium | M1 §9; M2 §8; M3 §8 | `-m postgres` only runs marked tests; clean fakes hide small-model quirks; no mid-tick crash test. | Parametrise the DB fixture over both dialects when `ORCH_TEST_POSTGRES_URL` is set; "noisy small-model" FakeProvider mode (fences, preambles, smart quotes); simulated mid-tick crash test. |

**Independent corroboration (themes raised by more than one reviewer):** immutability gaps (GH1, MC2, GE2) · consensus/evaluation cycles (GH2, MC3, GE3) · priority & starvation (GH3, MC4, GE5) · view portability & migrations (GH4, MC1, GE1) · crash recovery & side effects (GH5, MC6, GE4) · claims/concurrency (GH6, MC6, GE4) · contracts for small models (GH7, MC5, GE6) · branching runaway (MC4, GE7) · test strategy (GH8, MC8, GE8) · autonomy realism (MC7).
